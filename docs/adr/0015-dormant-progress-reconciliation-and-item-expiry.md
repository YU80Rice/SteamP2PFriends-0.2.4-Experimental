# 0015: 无人区域进度补算与掉落物到期清理

用户在 2026-10-07 的 Q1 选择保持原生玩法进度，同时避免无人区域持续实时运算：希望在重新进入时，依据休眠时长及原生规则结算燃油、作物与雨水等变化。掉落物另按对应配置到期移除，不等待重新进入。该决策适用于房间仍运行的情形；记录来源是 [原生职责复用与按需运行的边界是什么](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/ticket.md) 的 Q1 用户原文。

## 已决边界

- 默认方向是休眠与恢复时的进度补算，玩法结果以原生规则为依据；不选择无人区域暂停玩法进度，也不选择逐帧重演全部休眠过程。
- 掉落物到期清理独立于空间重入，需要在无人期间处理。此处冻结行为目标，不冻结调度机制、允许的清理延迟或时钟类型。
- 原生世界业务数据继续归 Native State Authority；租约释放不直接授权删除这些数据。

## 取舍与尚未冻结的内容

保持全图持续运算会延续原生执行成本；无人即暂停会改变玩家返回时的玩法进度。采用进度补算作为默认方向，但不以本条决策证明所有对象都可以只按时间差准确复原。

发电机阶段、作物时间戳、天气事件和遮挡属于不同依据，见 [Resource/Object/Building 原生事实](../../.scratch/map-c-stage-world-state-migration/ticket-u3ds-world-state-facts/findings-objects-buildings.md) 的事实 32–36。天气/遮挡历史、持续电力交互、无法补算对象的处理、误差边界与会话结束前结算仍须问询；未经证明不把“离开时长乘速率”当作所有领域的通用公式。

具体规则补查见 [无人进度补算的原生规则补查](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/native-progress-facts.md)：雨桶按事件置满，供电设备依赖有效供电时段；这些事实尚未裁定无人期间的关键事件处理策略。
