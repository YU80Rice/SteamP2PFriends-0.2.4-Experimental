# 0017: 世界存档前结算无人区域进度

用户在 2026-10-07 的 Q3 同意推荐 A：自动/手动世界保存和正常关房保存前，将原生可保存对象的无人进度结算到保存时点，再交给原生保存链。来源是 [原生职责复用与按需运行的边界是什么](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/ticket.md) 的 Q3 及用户“同意采取推荐”。本条扩展 [0015: 无人区域进度补算与掉落物到期清理](0015-dormant-progress-reconciliation-and-item-expiry.md) 的结算触发点，保留其历史记录。

## 取舍

只在返区时结算，会使未返区便保存/退出的对象留下旧燃油或旧进度。选择在世界保存边界先结算，保留运行期间应发生的原生玩法结果；这会增加保存时的处理成本，具体预算仍需设计。原生核心世界保存链与正常退出保存见 [Item、存档、全局与玩家状态入口盘点](../../.scratch/map-c-stage-world-state-migration/ticket-u3ds-world-state-facts/findings-items-global.md) 的事实 21–24。

## 适用边界

- 结算房间运行期间的无人进度，只写入原生本来保存的对象与字段；正常世界保存是触发点，单个玩家断线仅保存该玩家的路径不自动升级为世界结算。
- 不新增地面物品跨会话保存，也不新增关房期间的离线模拟；异常崩溃不因此获得正常保存保证。
- 保存结算不授予区域持续逐帧执行资格；允许的必要关键事件处理继续遵循 [0016: 休眠期间允许必要的关键事件处理](0016-key-event-processing-during-dormancy.md)。
