# 0020: 自然物品返区结算当前结果，省略无人期间中间刷新批次

用户在 Q7 以旧子弹过期、无人期不继续计算刷新、返区补出新物资并重新计时的例子表态“如果这样描述，我更同意采取推荐A”。据此选择 Q7 的 A 方向，细化 [0019: Item 全图准备数据，首次需求启动自然周期，无人时返区补算](0019-item-preparation-and-demand-started-natural-cycle.md)。完整原文与澄清见 [原生职责复用与按需运行的边界是什么](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/ticket.md) 的 Q7。

## 行为与取舍

- 无人期不逐轮计算自然物品随机再生；返区以当前权威数据结算到期旧自然物品，再按原生刷新资格、数量、点位和抽表规则尝试补充当前缺量。
- 新实际补出的物品从本次生成时计时；仍未到期的旧物品保留自身年龄，不因返区重置寿命。自然物品寿命取配置，“30 分钟”只是问询示例。
- 到期资格随已启动的玩法时间推进；本策略要求最晚在返区构建可用基线/允许交互前排除过期旧自然物品，不将用户例子解释为必须在无人期阈值瞬间逐件执行权威删除。
- 进入区域是结算触发，不是无条件生成命令；未满足刷新资格、数量已足、点位冲突或生成被否决时，可以没有新物品，不承诺补满。
- 实际掉落物的独立到期清理继续遵循 ADR 0019；不把它们并入自然物品延后结算。

选择省略中间随机批次降低返区计算量，但返回时的物资种类、数量和年龄不保证与原生 U3DS 持续全图巡检的历史结果完全一致，也不保证重现中间扩展回调副作用。

## 防重复与源码边界

原生周期刷新一次候选点只抽一个物品 ID；检查同一区域现存 ItemData 与候选点的距离平方 <4，成功后立即加入权威列表，后续尝试也会看到它。补算需保留这些约束并先清过期旧数据；不能在每次进区调用首次 generateItems 重建自然列表。

SDK 源码输入：`ItemManager.cs:774–839,847–907,1201–1269`、`LevelItems.cs:166–173`、`ItemTable.cs:95–135`、`ItemData.cs:26–33`；SDK 根为 `D:/Agent-工作目录/U3-SDK/Assets/Runtime/Assembly-CSharp/Unturned/`。上述距离检查不泛化为首次生成、跨区、物理移动或扩展改点后的所有物品都不会重叠。

计时基准、重复事件/重试提交防护、返区预算、失败处理及完整同步顺序仍待规格化；本条是政策决策，不是已实现或 Runtime 无缺陷保证。
