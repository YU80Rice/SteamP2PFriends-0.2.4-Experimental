# 0022: Item 正常体验沿用原生，等待与重试作为局部兜底

用户在 Q8 表示“按照原生的刷新规则，不是进入区域就准备好了吗？当然，推荐解法也是可以采取的”，Q9 选择推荐解法，并强调这些问题更像兜底，询问 U3DS 正常体验。因此正常路径沿用原生自动同步/模型展示和合法拾取，不人为增加每次进区可感知等待；Q8/Q9 推荐仅用于未就绪、异常或超时恢复。来源见 [原生职责复用与按需运行的边界是什么](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/ticket.md) 的 Q8/Q9。

## 已接受的边界

- 正常移动和其他领域玩法继续；物品按原生区域同步与实例化流程自动呈现，不要求整区所有模型齐全或新应用 ACK 后才继续游戏。
- 未就绪/异常时，不能把过期旧物资或失败结果当作正常可交互状态；允许暂缓受影响物资的呈现/拾取，不扩成每次进入区域的统一新门控。
- 有限自动恢复后仍失败，明确提示受影响区域物资暂不可用，允许重试；不默认要求重连，也不无限静默重试。
- 同步投递失败按观察者/区域隔离；若共同权威区域结算失败，依赖该区域数据的观察者都需一致处理，但无关区域/领域不因此停用。

Q8 不表示原生在客户端永远瞬时显示全部物品。原生服务器地图准备、区域数据发送和客户端模型实例化是不同阶段；源码对照见 [U3DS Item 正常加载与异常兜底的区别](../../.scratch/map-c-stage-world-state-migration/ticket-item-sync-preflight/findings-native-normal-experience.md)。

## 待规格化

恢复触发、期限/尝试次数、提示频率与重试入口需明确；不因此新增 LMN 依赖或预设新传输/ACK 协议。Q10 当前是对原生初始化的询问与对推荐稳定性的倾向，尚未另行裁定 SPF 开房/进图等待策略；数据准备不等于等待全图模型。既有 ADR 0019–0021 不改写，无生产实现或 Runtime PASS。
