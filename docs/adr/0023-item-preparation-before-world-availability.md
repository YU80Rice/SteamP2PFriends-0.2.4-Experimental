# 0023: 全图 Item 数据准备完成后开放相应联机运行

用户在 Q10 确认“是，确定”：沿用原生准备顺序，先完成全图物品数据准备，再开放相应联机运行；模型继续按附近需求加载，不变成每次进区等待。来源见 [原生职责复用与按需运行的边界是什么](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/ticket.md) 的 Q10。

数据准备完成是当前地图 Item 可用的前置条件，包含合法空区域；服务端网络身份建立、房间发布或 Host 活动标志不能代替该条件。准备须在原生区域数组、地图物资点及资产输入可用后执行，不能为追求“先准备”而在这些输入尚未创建时运行生成。

开放条件针对数据与相应运行资格，不要求全图模型实例化、全图客户端快照或新增 Item ACK；不改成每区等待界面。准备失败不得误报完成或以不完整物资状态提供正常交互，恢复继续遵循 [0022: Item 正常体验沿用原生，等待与重试作为局部兜底](0022-native-item-experience-with-local-failure-recovery.md)。

本条确定用户可见顺序，不冻结 Host/地图回调 API 或批量预算，不新增 LMN 依赖、地面物品持久化或其他域补算引擎。Item 的数据准备、首次启计和返区结算仍是不同状态；ADR 0019–0022 的历史记录不改写。
