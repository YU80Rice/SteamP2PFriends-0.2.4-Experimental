# 0019: Item 全图准备数据，首次需求启动自然周期，无人时返区补算

用户在 2026-10-07 提出全图预生成物品数据、玩家进入区域才启动自然消失/刷新，并在 Q6 回答“同意推荐B，这样子更多的是数据计算，减少模型渲染的消耗”。本条承接 Q5 候选和 Q6 的 B：首次启动后无人时停止实时自然周期执行，返区按原生规则补算，实际掉落物独立继续到期清理。完整问询见 [原生职责复用与按需运行的边界是什么](../../.scratch/map-c-stage-world-state-migration/ticket-runtime-duty-boundary/ticket.md)。

## 已接受的行为

- 会话开始全图准备自然 ItemData；没有领域需求的区域保留预生成数据，尚未启动自然物品周期。
- 首次 Item 领域需求启动该区域自然物品计时；后续观察者加入或返区复用权威数据，不再次首次生成或重置计时。
- 已启动区域无人后停止实时自然周期执行；返区按原生规则结算无人期变化，玩法时间不是暂停。多人同区时按本域需求判断无人，不因某一个玩家离开便停止整个区域。
- 实际掉落物到期清理独立继续，未访问区域也不能让真实掉落永久存在。自然物品与实际掉落的行为区分细化 [0015: 无人区域进度补算与掉落物到期清理](0015-dormant-progress-reconciliation-and-item-expiry.md)，不改写其历史。

## 取舍与成本

相对 U3DS 开局便运行自然周期，本方案有意改变尚未访问区域的物资计时历史，并减少无人自然周期的持续执行。全图预生成的启动成本和权威数据内存仍保留；补算可能产生返区计算峰值。原生 generateItems 只构建 ItemData，全图准备本身不实例化全图模型，事实见 [Item、存档、全局与玩家状态入口盘点](../../.scratch/map-c-stage-world-state-migration/ticket-u3ds-world-state-facts/findings-items-global.md)。因此本决策主要调整周期计算资格，模型/渲染收益另由实例与可见性政策决定，尚未测量或授予 Runtime PASS。

## 未冻结的内容

原生 ItemData/ItemRegion 在创建时已记录时间，须定义首次启动的时间基准；具体时钟表示、滞回与休眠衔接、自然随机刷新补算语义/预算、基线前结算顺序和失败处理仍需规格化。

实际掉落的来源识别与对应配置也需核对：SDK 的僵尸/动物 dropItem 调用会把 dedicated 值作为 isDropped 参数，听主机下该标志不必然表示本政策的生成来源；不能只据 isDropped 判定休眠资格，也未批准统一改写该标志。详见本轮问询记录的源码输入。本条不新增地面物品持久化，不冻结实施接口或一般化补算引擎。
