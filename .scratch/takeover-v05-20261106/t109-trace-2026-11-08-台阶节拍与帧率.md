## 9. 结论

### 9.1 已确认（原始 trace 直接支持）

1. **gate 探针字段不存在**：7 类记录的键名与原文行扫描均 0 命中；仅有旧字段 `model_pos`（全 null）与 `model_endpoint_resolved`（全 true）。
2. **权威位置以台阶刷新**：17,054 个渲染帧中 15,963 帧（93.603%）位置完全不变，仅 1,090 帧（6.391%）发生变化；相邻变化间隔 p50=5 帧/**80.06 ms**、p10=2 帧/56.8 ms、p90=7 帧/105.7 ms、max=2,318 帧/33.64 s。
3. **步长集中在两个离散值**：3D p50/p90/max=**0.360008/0.560008/1.079948 U**；XZ=0.359968/0.559958/1.032040 U；\|Y\|=0.080501/0.164948/0.560001 U；656 次落在 0.36 U 附近、382 次落在 0.56 U 附近，合计 95.2%。
4. **v_pos 与 a_pos 逐帧全等**：17,054/17,054（100%）；`authority_pos` 同样 100% 相等；`last_update_pos` 93.544% 相等，差异 ≤0.005058 U。
5. **渲染帧间隔不是恒定 60 Hz**：p50=13.678 ms、p90=21.140 ms、p99=46.286 ms、max=199.491 ms；>33.4 ms 占 2.481%，>50 ms 占 0.821%，>100 ms 占 0.164%；全程平均 68.764 fps。
6. **时间尺度对比**：台阶中位周期 80.06 ms 是渲染帧中位间隔 13.678 ms 的 **5.85 倍**；台阶只发生在 6.4% 的渲染帧上，其余 93.6% 帧画面位置保持不变。
7. **SIM/RX 节拍与台阶节拍同量级**：SIM 12.428 次/s、RX 12.491 次/s，SIM 位置变化间隔 p50=0.079435 s；35.98% 的 SIM 应用才改变位置。
8. **条件性推论（仅用本 trace 数据）**：若假设渲染帧间隔完全均匀，按本 trace「v_pos 逐帧等于 a_pos、93.6% 帧位置不变、6.4% 帧跳 0.36/0.56 U」的字段形态，画面仍会以约 12.5 Hz、0.36/0.56 U 的台阶推进。因此「台阶形态」不依赖掉帧即可存在；同时本 trace 也确实存在 2.481% 的 >33.4 ms 长帧。

### 9.2 数据不足以下结论

- **不能证明 `v_pos` 就是实际模型渲染变换**：`model_pos` 全 null，`interpolation_unavailable` 全为 `model_pos`；只能证明探针记录的两个位置字段相等。
- **不能把「像掉帧」的主观观感与某一数据形态唯一对应**：本报告无同步录屏/帧计时外部测量，只有 trace 内部字段。
- **不能解释台阶为何是 12.5 Hz / 0.36 U 与 0.56 U**：本 trace 未记录采样策略、插值开关或网络时延分解；不推断根因。
- **不能解释 15 段 >1 s 的位置保持**（最长 33.64 s）：`right_censored_ranges` 只标注 144207–146037 为 RIGHT_CENSORED，未给出原因字段。
- **渲染侧 1,090 次变化 vs SIM 侧 1,109 次变化**相差 19 次，未逐一对齐。
- **`result.json` 判 `Unknown`/`INPUT_SEQ_MISSING`**（`strict_m1_events=0`）的原因不在本报告范围；本报告不依赖该判定，但该 run 的 M1 结论不能由本报告背书。

## 10. 复核注意与已知口径差异

1. 本 run 实测 **68.764 fps**，不是 60 Hz；任何「帧数 ÷ 帧率」的换算都会引入约 14.6% 误差，本报告一律使用 `mono_ticks / mono_frequency`。
2. 分位数为线性插值；`p10/p50/p90/p99/max` 与 n 一并给出，便于逐项复核。
3. 「相等」为 float 逐分量严格相等。v_pos 与 a_pos 是 100% 严格相等；last_update_pos 与 a_pos 有 1,101 帧存在 ≤0.005058 U 的差异，属记录/序列化路径差异，不影响结论。
4. `result.sim_root_span_3d_u=1.173277` 只能在「窗内 SIM BEFORE+AFTER 且含 release 帧（fc ≤ candidate_b+1）」口径下复算到 1.173280（差 3×10⁻⁶）；若只取 SIM AFTER 则得 1.114939（差 0.058 U）。引用该字段时需注明口径。
