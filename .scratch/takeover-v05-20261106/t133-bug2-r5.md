## 2. R26-01..05 逐条

### R26-01（medium）注册结果必须被采纳
- 文件：`Core/Registration/SteamP2PFriendsPlugin.PatchRegistrationDiagnosticsModules.cs:82-89`
- 改动：原 `ok = ApplyGunshotModuleOutcome(ok, _harmony);` 改为
  ```csharp
  if (!ApplyGunshotModuleOutcome(ok, _harmony))
  {
      ok = false;
  }
  ```
- 守护：Bug2-34 `Test_DiagnosticsStageAdoptsModuleResult` 读取 `InitializeDiagnosticStage` 的 IL，定位唯一 `ApplyGunshotModuleOutcome` call，断言其后紧跟 `Brtrue`/`Brtrue_S`。丢弃返回值会变成 `pop`，反转条件会变成 `brfalse`，两种变异都会被同一条用例抓到。

### R26-02（medium）音频源反射解析不得静默失效
- 文件：`Core/Patches/GunshotHostAudio/GunshotHostAudioRuntime.cs`（`GetGunshotAudioSource`，原 :581 附近）
- 改动：
  * 新增 `private static Func<UseableGun, AudioSource> _gunshotAudioSourceGetter;`，用 `DynamicMethod`（`Ldarg_0` / `Ldfld` / `Ret`）编译字段读取委托，避免 `FieldInfo.GetValue` 在非 Unity 宿主触发 `UseableGun` cctor 的 ECall `SecurityException`。
  * 解析流程：probe 缝优先 → `gun == null` 返回 null → `AccessTools.Field(typeof(UseableGun), "gunshotAudioSource")`（找不到返回 null）→ 编译 getter → 调用 getter。
- 守护：Bug2-35 `Test_AudioSourceReflectionContract` 断言字段存在且类型为 `AudioSource`，并用真实反射 getter 读回同一实例。首轮该用例曾因 `FormatterServices` 造出的 `UseableGun` 的 `m_CachedPtr == 0` 被 Unity 运算符判 fake-null 而失败，已通过给 `UnityEngine.Object` 基类字段注入 `m_CachedPtr = 1` 修复（该路径只读字段、不解引用原生指针）。
- note：解析失败时 `AudioSourcePresent=false`，该 fire 不满足门控、gate 行输出 `audioSource=0`，属 fail-closed 而非静默补偿。

### R26-03（low）删除不可达的插入数守卫
