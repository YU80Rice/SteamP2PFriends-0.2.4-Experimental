## 5. 技术影响范围（证据层事实，裁决待 GPT Architect）

### 5.1 移动：剔除窗口已定位，但归属未定

异常窗口边界极干净（33 秒内 8 条非零，其余全 0），cv 探针为 `PlayerManagerCullingDiagnosticPatch`。**待裁决问题**：`totalPlayersToSend=0` 是 SDK 原有剔除达到极值，还是 SPF Multi-Observer 的发送抑制？两条独立探针互证"确实没发"，但"为什么没发"未定。

### 5.2 声音：收件人集合已在源码级定位

`Assets/Runtime/Assembly-CSharp/Unturned/Useable/UseableGun.cs`：

- `:864` `askShoot(CSteamID)` → `ReceivePlayShoot()`
- `:867` `private static readonly ClientInstanceMethod SendPlayShoot = ClientInstanceMethod.Get(typeof(UseableGun), nameof(ReceivePlayShoot));`
- `:914` `if (Provider.isServer) { SendPlayShoot.Invoke(GetNetId(), ENetReliability.Unreliable, channel.GatherRemoteClientConnectionsWithinSphereExcludingOwner(transform.position, EffectManager.INSANE)); }`

`Unturned/Provider/SteamChannel.cs:160-178`：

```
foreach (SteamPlayer potentialRecipient in Provider.clients)
{
#if !DEDICATED_SERVER
    if (potentialRecipient.IsLocalServerHost)
        continue;
#endif
    ...
}
```

`Provider.cs:543/568` 同样 `continue` 跳过 `IsLocalServerHost`。

即：**枪声这一条 NetInvokable 的收件人集合在编译期就排除了 Listen Host，且 `Invoke` 不带 loopback。** 这与症状矩阵完全吻合（客机→主机缺；主机→客机正常；客机↔客机正常）。

**但必须回答的反问**（交给 Architect，不能由 Captain 裁定）：原版 Unturned listen-host 下主机能听到客机枪声，说明原版另有补偿路径（很可能是服务端本地播放）。那么 SPF 是在哪一层拆掉了这个补偿——自建 transport？Multi-Observer 把射击改由观察者转发？还是关掉了服务端本地音频？**这是 Bug2 唯一还缺的源码事实。**

### 5.3 队伍：机制清楚，卡在工程可交付性
