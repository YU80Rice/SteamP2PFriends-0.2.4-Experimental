`WhitelistTests/Evidence/Runtime/GunshotHostAudioTests.cs`（Bug2-34，`:883-906`）在 `GunshotStageOnlyForTest = true` 下断言：

1. `PriorStageFailedForTest=false` + 模块成功 → stage `true`；
2. `PriorStageFailedForTest=true` + 模块成功 → stage `false`（丢弃前序失败必红）；
3. 模块失败 + 前序成功 → `false`；
4. 模块失败 + 前序失败 → `false`；
finally 调 `ResetDiagnosticsStageForTest()` 与清模块接缝。

## 6. 为什么这样能防同类回归

- 旧守卫的隔离模式让 `ok` 起点恒为 true，因此「把前序失败硬置 true」或「只保留模块结果」两类变异在语义上等价于起点变化，用例看不见。
- 现在 `ok` 的起点由显式、可注入的 `PriorStageFailedForTest` 决定，Bug2-34 同时固定 priorFail × moduleOk 四种组合；任何「丢弃前序 ok」或「把前序失败置 true」的实现都会让 (true,true,priorFail=true) 期望 false 的断言失败。
- R28-02 去掉生产方法上的测试参数，测试改用可 Reset 的内部开关，避免生产签名被测试需求污染。
