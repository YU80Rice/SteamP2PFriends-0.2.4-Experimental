**不追认 t18 的逐订阅者异常隔离；要求回退为委托快照的单次正常 multicast 调用。F4 不补全旧账字段，收紧为“保留可核验的退役标识”。** 两者均不是交给实现者自由选择的方案。

- **flags 语义回退是 0.2.4.11-preview 出包前置**：当前拆分循环尚未回退，不能按现字节出包；回退实现、改写 Bug3-33 并对最终候选重建/回归、独立双轴核验后，才解除本冲突门。
- **F4 无新增生产字段前置**：现有退役元数据满足本裁决，字面差距由下文有效替换条款关闭，不要求 append-only 历史或驻留旧计数。
- 本裁决不替代工程轴 r3 的其他结论，也不关闭 T1a/T1b/T2/T3/T4 未完成验证。preview 身份不等于 Bug3 Green 或三 Bug 正式交付。

## 2. 冲突证据与裁决理由

| 输入 | 本次相关事实 |
|---|---|
| [T12 架构条款 §7.3:155](review-eng-t3.md#L149-L156) | 单次 multicast，外层捕获 NotificationFailed；首个监听者抛错可中断后续，禁止私拆列表与自动整批重发 |
| [工程轴 r2 F5](review-eng-t16.md#L96-L99) | 要求拆 GetInvocationList 逐订阅者隔离或针对性重发，与上述明确契约冲突 |
| [t18 当前生产片段](../../Core/Patches/P2PGroupStateRecovery/P2PGroupStateRecoveryPatch.cs#L768-L812) | GetInvocationList 循环逐个 catch，异常后继续；不是原生 multicast 的异常语义 |
| [规格轴 r3 O1/O3](review-spec-t18-r3.md#L129-L134) | 正确识别为两轴冲突，不将照工程轴实施归责为擅自偏离；F4 留给 Architect 措辞裁决 |
| [T12 副作用边界](review-eng-t3.md#L141-L147) | flags 监听者不只 UI，含 LevelObject 条件刷新及未知第三方副作用，不能把继续执行后续回调当成无风险强化 |

选择回退的依据不是“旧文档不能改”，而是本次修复只获准补足**真实 bulk 数据就绪后的一次原生型通知**，没有证据要求改造原生通知的失败模型。隔离可提高部分订阅者到达率，但会在原先已异常中止的场景继续执行其他未知回调；这不是修复缺失通知的必要条件。工程轴关于部分投递风险的观察成立，其建议的逐个隔离与针对性重发在本轮不采纳。

[需求契约 §7 R1–R3](requirements-v2.md#L101-L107) 要求实际候选回归、非目标不干预、分项关闭，没有要求“任何监听者抛错后也必须继续投递所有监听者”。本裁决保留 T12 既定兼容语义，**requirements-v2 无需同步勘误，冻结字节不改**；工程轴 F5 以本裁决调整关闭依据，不再以逐订阅者继续执行为通过标准。

## 3. flags 回退的精确执行指令

1. 保留现有资格门、同 epoch/map/token 校验、真实 load 正常返回资格及 `NotifyAttempts` 在调用前提交的顺序。只将 [TryNotifyFlagsCore 的订阅者循环](../../Core/Patches/P2PGroupStateRecovery/P2PGroupStateRecoveryPatch.cs#L740-L812) 改回对已捕获的 `FlagsUpdated handler` **调用一次 `handler()`**；不另枚举、排序、去重、延时或逐项重发。回调快照仍保持正常 multicast 的注册顺序及重复注册项语义，不承诺不同委托实例对应的同一方法只执行一次。
2. 整个 `handler()` 用一层异常处理：正常全部返回才记通知成功；任一订阅者抛错即停止后续订阅者、记录一次 `NotificationFailed`/错误与当前租约，不能虚报“所有监听者已通知”。回调已产生的副作用不回滚，已消费的 attempt 不恢复。
3. 异常后仍不得重试 load、整批通知或只重试未执行订阅者；同 token 后续组回调、watchdog、重复入口仍拒绝补发。通知期间的重入保护、finally 清理和独立组状态发布顺序保持，不能为回退连带撤销 T12 的 exactly-once 防护。
4. 不再以 `NotifyFailedSubscribers` 的精准订阅者失败数为验收；单次 multicast 只观察到了一个传播异常，未执行者可能成功也可能失败，不能统计或推断。现有通用 `NotifyFailed` 足以记录此次通知尝试失败；日志不得继续写“others still notified”。无需为了本裁决重构整套账本。

### Bug3-33 必须改写，不能直接删掉

当前 [用例断言](../../WhitelistTests/Evidence/Runtime/P2PGroupStateRecoveryRuntimeTests.cs#L688-L698) 要求首个抛错后第二个仍调用一次，须反向改成兼容性失败模型检查；[正式入口](../../WhitelistTests/Program.cs#L881-L883) 保留 Bug3-33 ID，名称同步改成“Multicast Stops On Subscriber Exception, No Retry”等准确表述。

测试在生产通知接缝上构造同一个已满足 load 成功资格的合法租约与非空 payload，在委托快照中依次放 A（记录成功）、B（记录后抛错）、C（记录成功）；这种接缝用例不冒称真实存档 load 成功：

| 断言 | 必须结果 |
|---|---|
| 第一次通知 | 记录顺序仅 A、B；A=1、B=1、C=0；返回失败而不是成功 |
| 账本 | RealLoadSuccess=1、NotifyAttempts=1、NotifyFailed=1；通知成功数不增长 |
| 同 token 再通知 | 拒绝，A/B/C 均不再增长，不再调用原生 load；不能把失败重置成可重试 |
| 异常后的其他阶段 | 通知 finally/reentry guard 清理仍有效，独立组发布未被改成随异常直接丢失；已有相关用例保持 |

删除“第二订阅者必须为1”“精准失败订阅者计数=1”的旧隔离语义断言。正常无异常委托的既有正控仍应全部按原顺序执行一次；回退后若再引入逐个 catch 继续 C，Bug3-33 必须红。该用例只验证生产通知接缝的失败语义，不冒充真实存档 T1a Green。

### 明确登记的限制，而非静默豁免

**KNOWN-MULTICAST-PARTIAL-DELIVERY**：首个监听者抛错前已执行者可能有副作用，后续监听者可能没有收到本次 bulk 就绪，导致本机 UI 或 LevelObject 条件表现未刷新；错误需可见且状态为 NotificationFailed，完整表现验收不授 PASS。正常退出/完整重启按明确流程重新初始化，不由模块自动重播。

这是保持原生失败模型的兼容性限制，**不是“用户已接受任何正常场景通知失败”**。若普通内置监听者在候选正常流程中实际抛错，仍按真实缺陷处理，不能援引本限制把常规失败宣布成功或绕过出包门。第三方监听者可有任意副作用，不能笼统声称该失败模型绝不会影响游戏事实。

## 4. F4：接受退役元数据，正式收紧矩阵⑤

[ResetSession:211–228](../../Core/Patches/P2PGroupStateRecovery/GroupStateRecoveryCore.cs#L211-L228) 在活动账 Reset 前保存 `RetiredLeases/LastRetiredToken/LastRetiredEpoch`，随后重置活动账。它没有保留旧 `RealLoadSuccess/NotifyAttempts` 全字段，不把它宣传成完整历史账。[规格轴 F4 证据](review-spec-t18-r3.md#L85-L89) 足以支持“旧租约曾存在且已退役，新账从零开始”的可核验区分。

**本文件自发布起，将 [T12 §7.4 矩阵⑤](review-eng-t3.md#L166-L174) 中“旧账保留历史值，不新增”的有效措辞替换为：**

> **旧 epoch/token 跨入二局：保留可核验的退役标识（退役累计数、最近退役 token/epoch）；活动账可重置，旧租约在二局触发的本模块受控 load/补发本次增量均为0。无需把旧 RealLoadSuccess、NotifyAttempts 等计数继续驻留内存。**

这是该一格的收紧，不削弱 `NotifyAttempts≤RealLoadSuccess≤1` 对每个**有效活动租约**的约束，也不允许把旧授权套给新局。旧报告按历史原文保留以维护审查绑定；后续审查引用本文件替换条款，不要求实现者自行改冻结原报告或需求。

[Bug3-40 对应复审记录](review-spec-t18-r3.md#L85-L89) 保持有效：旧非零 token/epoch 在 Reset 前被记为最近退役，新活动账 Token=0/State=None、epoch递增；无活动租约的边界不能凭空多退休一次。另保持旧 token 后到回调不执行 load/补发的负控，以及新 epoch/token 成功后的正控；**不要求新增生产字段/无限历史容器**。若需复核跨界前的计数，由测试在 Reset 前持有只读断言快照、比较实际原生调用/哨兵的跨界增量，不把新账的零伪称旧历史计数未变。

## 5. 影响分级与 preview 处置

| 档位 | 本裁决中的对应面 | 门禁 |
|---|---|---|
| **影响服务端事实正确性** | 真实 load≤1、组/flags已装载事实、epoch隔离、旧 token 不兑现及 members 不增等防护；本次均不改变，也不准随通知回退而放松 | 若回退导致重读/旧租约复活/额外权威写入，硬阻塞 preview；不接受以“只通知”降级 |
| **仅影响本机表现/可观测性（本模块直接变化）** | multicast 异常后后续回调中断；通知失败/部分投递的可见记录。不是更改原生持久化或组表算法；监听者可能触及 LevelObject，不能简化成纯 UI | 当前逐项隔离与批准语义不符，**回退+改写用例并核验前阻塞 preview**；异常风险按上节登记，正常流失败仍是缺陷 |
| **仅影响措辞与文档一致性** | F4 旧账字段保留措辞比现有退役标识实现更宽；本次收紧定义与当前边界证据一致 | 本裁决发布即消除此处字面阻塞，不新增生产字段前置；不能据此声称拥有完整历史账 |

第三方回调的任意 gameplay 写入不属于“本机表现”保证；一旦实际观察到服务端事实异常，按第一档处理。本裁决不是对任意插件生态给出无副作用担保。
