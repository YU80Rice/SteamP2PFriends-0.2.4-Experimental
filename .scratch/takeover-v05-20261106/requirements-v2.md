## 2. 验收手段与共同判读规则

每条判据以下列标签注明判定手段；一个标签的通过不能替代另一个标签。

- **[自动化]**：实际生产 DLL/原生方法的可执行断言，或既有 formal 回归；记录 Red、Green、入口、输入、候选身份和退出码。独立复制的恢复/平滑/发声算法不算生产行为测试。
- **[Unity-SDK 集成]**：需要真实 Unity 对象、原生游戏入口或播放/呈现终端的观测；SDK 是集成资料，不以完整 Unity Editor 启动为默认前置。Unity ECall/许可阻断时写明具体边界，结果为 UNKNOWN，不虚构 PASS。
- **[真机 1H+1G]**：真实 Host 和 Guest 的画面、UI、可听结果及对应日志。记录各端版本/SHA-256/MVID、动作时间及听者/观察者；身份不一致则该候选结果不可用于验收。

UNKNOWN 是合法结果，但不是通过；必须写“缺哪一端/哪个观测点”。现有 1H+1G 无第二位 Guest，因此 Guest→Guest 永远是 **UNKNOWN（本轮拓扑不可验证）**。只能用后续 **真机 1H+2G** 关闭该列，禁止把它塞进双人结果。仓库最终三端门禁继续保留；下面双人定向验收不取代它，也不要求重新执行全部历史调查。

验收等待统一使用有界条件：自动化/集成测试提供开始条件、完成事件和超时；实机队伍 UI 使用进入可操作状态后 10 秒、离组点击后 5 秒作为本轮观测窗口。该窗口是判读协议，不是新产品网络超时常量；窗口内未收敛记失败，仪表缺失记 UNKNOWN，不无限等待。移动测量协议另见 §3.1。

### 3.1 移动最小可判定协议

这是新增的验收测量协议，不是声称用户曾测得下述阈值，更不规定修复算法。Architect 可以据真实呈现对象校准采样点，但不得在看到候选结果后放宽阈值来制造 Green。

1. **M1/M2 条件**：平坦无遮挡地面、无碰撞、恒定前进输入；走和跑各采集 10 秒，去除开始/停止过渡各 0.5 秒；每帧记录单调时间、实际帧时长、输入、权威坐标、可见模型坐标与 yaw。采样坐标必须在同一坐标系，区分模拟根与渲染对象，不用网络发送计数代替。记录 timeScale，主判段要求 timeScale=1 且无 ESC 暂停；不满足条件的段不能拿来归因或宣称通过。
2. **停帧补步判据**：在有效持续前进段，若权威位置继续推进、可见模型连续至少 3 个渲染帧位移不超过位置记录分辨率 ε，随后一次可见位移超过该段原生最大移动速度 × 实际帧间隔 + ε，计为一次失败；走/跑段该失败数必须为 0。ε 取实际记录精度且不得大于 0.01 游戏单位；速度上限取当前真实配置，不以历史 0.08 秒广播周期代替帧间隔。若采样精度不足，结果 UNKNOWN，先修测量能力。
3. **静止 M3**：停止过渡结束后静止 5 秒，可见位置最大偏差不超过 ε；记录原生待机动画，不把骨骼呼吸误算成位置漂移。
4. **跳跃/转向 M2**：至少各执行 3 次，标注起落/方向变化时点；不得出现输入保持且权威持续变化时，可见位置/朝向连续至少 3 帧保持后一次集中跳至新值的片段。角度分辨率另行记录，使用最短角差以排除 359°→0°误报。
5. **瞬移/校正 M3**：各驱动一次真实原生合法事件；在原生事件完成或原生既定收敛边界处，可见实体应落在权威目标 ε 范围内，且静止后不再回到旧轨迹。边界、目标坐标、最终偏差必须写进结果；原生入口不可执行时该项 UNKNOWN，不能凭“支持瞬移”的代码断言通过。
6. **M4 同条件反向检查**：录制/轨迹里每个失败片段都有起止帧号，不能只交“看起来流畅”。1H+2G 时另对第二 Guest 重复；未做前不声称多 Guest 已通过。

Host 剔除计数全剔除、remoteUpdates 连续为零是有价值的调查证据，不直接等于 M1/M2 失败轨迹或确定根因。要求区分 ESC/timeScale 混淆，不将“观察到剔除”直接翻译为“必须改剔除”。

### 4.2 诊断配置归属与唯一启用判据（新增：T152 / T145-F1）

本节与 [配置合并架构追认 §3–5](architecture-ruling-config-consolidation.md#L28-L48) 对齐；该追认取代 T88 中旧独立 cfg 的配置归属与核对口径，不取代本需求其他功能判据。下列 CFG-01–04 是新增覆盖/核对项编号，不表示已有同号自动化用例或已取得通过证据。

1. **旧配置失效；覆盖点 CFG-01 [自动化]（读取/绑定路径与旧值隔离）**：自 **0.2.4.11** 起，旧三个独立 cfg（`SteamP2PFriends.Bug1Probe.cfg`、`SteamP2PFriends.Bug1Gate.cfg`、`SteamP2PFriends.Bug2HostGunshot.cfg`）不再被读取，其中的 `Enable=true` **不迁移、不生效、无回退读取**；三个开关仅绑定主 cfg `com.yu80rice.steamp2pfriends.cfg`。对照主 cfg 缺项或显式 false、旧 cfg 分别写 true 与旧 cfg 不存在时的读取路径及最终值；任何分支仍读取旧 cfg、将旧值写入主 cfg，或仅凭旧值使对应开关生效，均算违反。旧文件可以保留供人工参考，但不是受支持的启用入口。

2. **唯一启用判据；覆盖点 CFG-02 [自动化 / 真机 1H+1G]（本次启动自证与缺失/不符拒收）**：只认当前被测进程、**本次启动**的完整自证行 `[Diagnostics] configPath=<绝对路径> bug1Probe=<bool> bug1Gate=<bool> bug2HostGunshot=<bool>`；路径须为本次实际使用的主 cfg 绝对路径，三个布尔须与测试前声明的预期逐项一致。声称某项已启用必须对应 `True`；单项试验允许其他项如实为 `False`，不新增三项联动要求。**缺该行、路径缺失/非绝对/不符，或三布尔任一缺失/与预期不符，即视为本轮未启用，不得用该轮日志归因 Bug1/Bug2**，须修正配置/证据后重跑。以 cfg 文本 true、另一进程或旧启动日志代替，或在上述拒收条件下继续记为已启用/据此归因，均算违反。

3. **用户值不得覆盖；覆盖点 CFG-03 [自动化]（缺项首次绑定与已保存值重启/升级对照）**：主 cfg 中用户已保存的 **true 必须被尊重**，已保存的 false 也不得擅改；**默认 false 仅是首次生成或缺项绑定的缺省值，不得在每次启动、升级或入口注册时写回覆盖用户值**，亦不得从旧独立 cfg 补入 true。对照启动/升级前后主 cfg 的已保存值及自证三布尔；保存 true 后被重置为 false、保存 false 后被改为 true，或缺项时吸收旧 cfg true，均算违反。配置为 True 仍受原有角色、目标、profile、预算等运行资格限制，不等同执行成功。

4. **配置契约的覆盖边界；覆盖点 CFG-04（打包前置文档核对项）及 CFG-02（启动自证核对项）**：打包前核对 **DLL 与升级/测试说明同代次**，说明必须明示旧三个 cfg 停用且值不迁移的破坏性兼容变更，并指引按自证 `configPath` 在主 cfg 显式设置后复核三布尔。说明仍指向旧 cfg、说明与 DLL 代次不符、只埋入实现报告而未告知测试入口，均算违反。本节只核对配置归属与启用事实，**不授予 Bug1 闸门成立或 M1/M2 PASS，不授予 Bug2 实机可听或 S1–S4 PASS，不授予任何功能 PASS 或发布许可**；将自证值 True 或文档核对通过替代这些验收，即算违反。关闭任意或全部开关仍须保留 [架构追认 §4](architecture-ruling-config-consolidation.md#L38-L44) 列明的 Bug3 安全内核；以关闭诊断为由关闭保存保护也算违反。
