## 2. R27-01：`FoldGunshotOutcome`

- `Core/Registration/SteamP2PFriendsPlugin.PatchRegistrationDiagnosticsModules.cs`
  - `internal static bool FoldGunshotOutcome(bool stageOk, bool moduleOk)`：`return stageOk && moduleOk;`（唯一语义，不读静态状态）。
  - stage 生产接线：
    ```csharp
    bool gunshotModuleOk = ApplyGunshotModuleOutcome(true, _harmony);
    ok = FoldGunshotOutcome(ok, gunshotModuleOk);
    ```
- stage 级语义可测：为让「结果被采纳」这条 stage 语句本身可被用例观察，`InitializeDiagnosticStage` 增加测试用可选参数 `bool gunshotStageOnlyForTest = false`；为 true 时跳过无关模块，只执行上面的折叠加法并返回。生产调用不传该参数（`PatchRegistrationOrchestration.cs` 的 `Func<bool>` 注册点同步改为 `() => InitializeDiagnosticStage()`）。
- `WhitelistTests/Evidence/Runtime/GunshotHostAudioTests.cs` 的 `Test_DiagnosticsStageAdoptsModuleResult`（Bug2-34）：
  - `FoldGunshotOutcome` 四组真值表：只有 `(true,true)` 为 true；
  - `ApplyGunshotModuleOutcome` 在模块 false/true 两种接缝下的结果再喂给 Fold；
  - 反射调用 `InitializeDiagnosticStage(true)`（`FormatterServices` 造 plugin 实例）：模块失败必须返回 false，模块成功必须返回 true。
- 变异 M1c 把 stage 语句 `ok = FoldGunshotOutcome(ok, gunshotModuleOk);` 改成 `ok = true;` → Bug2-34 红（`stage must adopt module failure（把 ok 写死 true 时必须红）`）。

## 7. 为什么这样能防同类回归

- R27-01 的旧守护是「call 后紧跟 brtrue」的 IL 形状，能防「不采纳」但不能防「采纳后被反转」。现在把语义收敛为纯函数：任意实现（`&&` 写成 `||`、恒 true、把 false 翻回 true）都会违反四组真值表；stage 级隔离执行再覆盖「stage 是否真的调用并采纳该函数」这条接线，因此 M1c 这种把语句改成 `ok = true;` 的语义反转也会红。
- R27-02 把「有音频源」从消费点内联表达式收敛为单一判定函数，并让用例从 Collect 接缝注入 null/非 null 两种探测结果，直接断言 `AudioSourcePresent` 与门控结果；把接线放宽成 `gun != null` 会立刻红。
- R27-03 把静默降级变成可观测状态（计数 + 原因），用例同时覆盖正常与异常路径，避免「catch 后随便返回 1」再次无信号。
