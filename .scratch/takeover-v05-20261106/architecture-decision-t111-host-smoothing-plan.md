## 2. 算法复用边界与Builder协议

原生算法参照[NSB结构与读取](../bug3-sdk-longpaths-20261030/Assets/Runtime/Assembly-CSharp/Unturned/Network/NetworkSnapshotBuffer.cs#L74-L142)及[写入/重置](../bug3-sdk-longpaths-20261030/Assets/Runtime/Assembly-CSharp/Unturned/Network/NetworkSnapshotBuffer.cs#L148-L187)。**复用思想/纯数学，不直接把原生NetworkSnapshotBuffer实例挂上Host的PlayerMovement。** 原客机路径及类型均不改，避免在本轮重构已工作的反向呈现。

| 可保留的部分 | 必须改写的部分 |
|---|---|
| 固定容量、读写索引、按序相邻样本、重置后不继承旧轨迹；可复用已存在且无原生副作用的纯容器实现 | Host每目标/epoch/连接/模型generation独立历史；容量固定16条，溢出不静默覆盖仍需读的样本，执行BACKLOG_RESET |
| 两点线性插值公式、Clamp01、空缓冲不向未知未来外推 | 生产者是目标原生walking simulate正常返回后的权威root；每个实际模拟序号一条，包括零位移、同帧批处理的不同模拟；不按渲染帧重复采样，不按收包/队列长度制造tick |
| 延迟以换取连续显示、已确认区间内回放、瞬移清历史 | 时间域为扩展后的实际native simulation序号：u=(s-s_origin)×RATE，RATE=0.08s；使用double和只读扩展序号处理回绕，不改原序号。mono记录实际到达与帧dt，不把包抖动直接变成运动速度 |
| 仅位置的Vector3.Lerp等价数学可原样使用 | 输出只取XZ，Y=0；不复用PitchYawSnapshotInfo对yaw/pitch的写回，不改朝向/原生姿态/动画速度 |
| 吃完已知段后保持最后确认点 | 不照抄NSB的`space>4`直接跳最新、隐式Time.realtimeSinceStartup或收包timestamp/readDelay策略；改为显式D、独立单调时钟、有原因码的重置与所有权撤销 |

固定实现顺序：

1. **采样**：只读Postfix观测原生正常返回；样本含s/u、mono、p、stance、目标及generation。原生异常不提交点、不吞异常。权威原点与当前画面profile不一致、非有限值、序号倒退/重复无法解释时停用并记录UNKNOWN，不猜补丢失点。
2. **预热**：第一轮只支持获准单目标、主相机、站姿平地走跑；按[T76支持域](bug1-minimal-render-interpolation-t76.md#L71-L99)门控。为明确消除启用瞬间倒退，arm/重入要求目标自然静止且支持状态/profile稳定至少0.5s，已有覆盖D的有效历史且这段位置在既定epsilon内一致、至少两点；否则Waiting/Warmup，保留原生呈现，不强停Guest。满足后设u_v=u_last-D并建立mono帧基准；因该段静止不发生旧位置回放。**这是首轮额外启用限制**，不是模组控制角色的授权。
3. **回放**：每个真实渲染帧用实际mono差推进u_v，推进量≤该dt，且不超过最后确认u；跨过多条样本用有界索引查找真实左右点，不限每帧只吃一条。P_v=(1-alpha)H(p_i)+alpha H(p_j)，alpha=Clamp01((u_v-u_i)/(u_j-u_i))，H为XZ投影。不能按“每帧一小步”或固定FPS推进，也不随到包次数加速。
4. **写出**：deltaXZ=P_v-H(当前原生权威root)，只加到本帧原生Model叶基线上；Y/rotation/scale完全不改。恢复上一帧自有偏移→原生Update/动画正常执行→LateUpdate唯一写者→主相机PreCull只核验，沿用[T76时序](bug1-minimal-render-interpolation-t76.md#L37-L57)。不得把P_v伪填成测量V。
5. **欠流/断续**：未来外推距离=0U；可走到最后已确认点然后hold。短欠流后只按此后实际dt前进，不一次性补回hold的时间；积压超过0.25s则清历史/对齐，不加速追赶。距最后有效样本mono≥0.25s、时钟异常、buffer溢出或偏移长度>nativeCap×0.25s+epsilon，恢复自有偏移并重置；重新满足静止预热门才重启。不把33.644s空洞缓存后补播。
6. **原生事件优先**：传送/纠正、出生/死亡、连接/epoch/实例换代、未知大跳、离开支持姿态/视野、装备/mesh/bones/material/相机profile变化，按T76撤销/暂停或sticky失败；不让上一代样本再次作用。跳/蹲趴/游泳/载具目前不平滑，但必须保留原生Y/动作并通过既定回归。正常站姿turn不改朝向，显著垂直运动暂停；具体判定须沿用真实原生状态/事件，未能绑定的切换记UNKNOWN并拒写，不用本轮统计max当传送阈值。

纯核心接口只接收值型样本、mono和配置，返回值型offset/状态；不引用Player/Transform/网络/存档。实际Unity挂接和writer另票实现。16条是有界内存设计值，不是16×80ms的回放许可；250ms安全限更先执行。

## 3. 显示延迟预算：默认130ms，允许80–150ms，不自动调参

**目标回放延迟D默认130ms；允许闭区间80–150ms，整毫秒配置；首轮试验固定130ms。** 新功能独立配置拟定`HostRemoteVisual.Enabled=false`及`PlaybackDelayMs=130`，不是现存可运行配置指令，不复用Bug1Probe/Gate.Enable。非有限/越界/非整毫秒配置拒绝arm并给原因，不能静默夹值；改D必须先停写/撤自有偏移、清历史、再人工arm并重新预热，不能运行中拖slider移动视觉时钟。首轮不做自适应延迟、预测外推或网络反馈调RATE。

依据是**产品取舍**：约80ms采样周期需要已知左右点；本轮p90变化间隔105.708ms，130ms留约24.3ms余量，且保持[T76的130ms初始值](bug1-minimal-render-interpolation-t76.md#L59-L69)。80ms是低延迟可选档，会更易欠流，不能宣称等效平滑；150ms是本轮有意接受的配置上限，不为掩盖长空洞无限增D。客机约100ms被接受是体验参考，不证明Host也必须恰好接受100/130ms；真实Host瞄准体验是否接受仍UNKNOWN，须A/B。低RTT不能消灭“用已确认样本插值”所需的显示等待，也不意味着只能用这一延迟；这是本轮不采用预测的选型。

必须区分三种量：D是视觉逻辑回放目标，不是增加网络RTT，不改变输入响应/碰撞模拟；真实采样mono到显示、逻辑u_last-u_v与实际几何滞后都要独立导出，不能只回报配置数值。离散相位/到达抖动/欠流会使实际显示年龄不恰等于D。**逻辑积压>250ms或有效供样中断≥250ms立即退回原生**，这是退化安全限，不是250ms的可调D；小于限值也不自动算体验合格。无完整供样/画面证据时实际年龄与效果仍UNKNOWN。

倍率1匀速下，vD量级的可见模型与原hitbox位差：默认走0.585U、跑0.91U；D=80ms时0.36/0.56U，D=150ms时0.675/1.05U，另有离散相位等误差，**不是严格最大距离保证**。额外偏移安全门仍用nativeCap×0.25s+epsilon，不能拿它宣称真实瞄准无影响。相机/准星/原枪口/命中逻辑保持不变；视觉与判定的偏差是已知成本，移动射击/近战体验变差即否决候选，而不是以“权威正确”强行验收。

## 4. 写入边界：通过能力对象和单一setter闭包落实

禁止项覆盖持续插值、初始化、错误回退、关闭和清理全过程：**原玩家root/PlayerMovement.transform、Third整体及其祖先、Skeleton与全部骨骼（含renderer.bones/rootBone树外引用）、Collider/Rigidbody/CharacterController/Joint及其节点/祖先、相机/aim/look、枪口/武器gameplay挂点/AudioSource，均绝不允许写平滑值。** 不改原生输入/tick/RATE/simulation/角色标志/状态发送/存档，不改骨骼动画时间、Collider.enabled或Physics.SyncTransforms来配合画面。临时移Third再在FixedUpdate前恢复仍然禁止；“Third每个子节点都在判定里”不是必要前提，只要它是判定骨骼祖先，就不能搬整个Third。

唯一候选写集是原`Third/Model_0`、`Model_1`中**经当前profile完整G证明合格的纯渲染叶**，仅position的共同world-XZ偏移。不是凡名字叫Model都准写；层级/组件/引用有未知闭包、叶本身或后代属于T94保护集合K时拒绝。全局未知mod行为不在保证内，支持范围必须固定且诚实。

Builder必须实现以下代码契约（以下是接口责任，不是要求新建通用权限框架）：

1. **值核心无写能力**：buffer/interpolator仅值输入输出；不接收Unity对象/delegate setter，不可反射/发包/触碰游戏状态。单元测试可决定性验证时钟与offset，不能凭此自证Unity安全。
2. **封闭lease**：一个内部私有构造的`QualifiedVisualLease`由资格工厂生成，绑定完整证据revision/profile、run/epoch/目标实例/连接与模型generation、精确renderer/Transform引用、允许position字段。不得暴露通用`Write(Transform,...)`、路径字符串解析写入或可变白名单；调用方只能给该lease与offset。PASS证据不能从bool配置伪造；真实指纹不匹配就无lease。
3. **工厂反交集门**：按[T94完整K](architecture-decision-t94-g-pose-coverage.md#L34-L58)取所有保护引用/父链、物理及未知组件检查；候选写节点不得是其中任一节点或会移动它们的祖先。原本不在准入闭包的可见附件不得临时藏掉以过门。运行时只读检查引用、generation、组件/profile仍一致，失效立即撤销资格；已销毁Unity对象不继续访问。
4. **唯一setter**：新插值功能的Transform.position/localPosition setter仅允许在一个内部`VisualLeafWriter`及其同一所有权restore路径，目标必须从有效lease内的只读引用表取得，每次写前检查同代次和精确引用身份。不通过`Transform.SetPositionAndRotation`、Translate、父链/reparent、矩阵/骨骼API或helper侧门绕开。仅Y不改还不够：rotation/scale/enabled/parent均不能写。cleanup也只能恢复仍等于本模块lastApplied的自有叶值；外来写者接管则ROLLBACK_UNCERTAIN、停写，不强覆旧快照。
5. **静态接线守卫+实际writer负控**：对新增功能的完整传递调用闭包查IL/调用点，setter目标只来自lease；删除精确引用门、把目标替换Third/Skeleton/一个子骨骼/Collider祖先、把cleanup改写root、引入另一setter路径，必须分别让守卫/实际writer测试变红。真实SDK中传入错误generation、未知profile及禁写节点必须在首个setter前拒绝，原物理/骨骼位快照不变；不是另造一个永远返回false的测试writer。实际合法叶位置写入/恢复也须跑，防止全拒绝的假安全。
6. **运行时核验而非事后洗白**：G用同帧完整骨骼位比较和实际表面残差；持续功能遵循静态禁写闭包并监测资格、相位、所有权和相机端点。发现任何权威/原骨骼/Collider/真实命中差异立刻sticky失败并正常退出实验。事后发现再还原不能把一次非法物理写变为安全。原生正常动画跨帧会变，不拿不同帧骨骼相等作为静止要求。

保证范围是经审代码闭包与明确profile的写能力隔离，辅以真实SDK负控/命中回归；不是靠命名约定，也不是宣称C#能隔离恶意反射或任意外部mod。缺少任何一项证据就不能宣布“绝不会影响判定”或签运行许可。

## 6. 长帧：独立观察项，不把全局帧调度优化塞进此次位置平滑

**2.481%的>33.4ms帧登记为独立已知性能观察项，根因UNKNOWN；本轮不承诺消灭它、不做通用GC/渲染/Unity调度重构。** 角色动作流畅、约80ms权威节拍及100%载体A=V支持位置阶梯是可单独修的主症状；这不等于长帧不存在或肉眼永不受影响。当前百分比是基线分布，不足以定位CPU/GPU/GC/磁盘/后台进程中的哪一个，也没有可信“改X即可修好”的证据。

纳入**本次候选的处理/验收责任**而不是新根因修复：使用全部真实mono帧dt推进；不把dt钳到16.7/33.4ms隐藏长帧，也不在一帧生成伪render样本。199.491ms长帧期间没有显示机会，插值不可能补造那些画面；下一帧按真实已确认轨迹推进，超过250ms等边界按§2安全退化。连续性判据仍用nativeCap×该帧实际dt+epsilon，不能把长帧造成的合法大步一律记成新增回补Bug。

A/B同时保留全帧时间p50/p90/p99/max、>33.4ms和>50ms比例、GC/模块开销及欠流/重置计数。可另做按帧时分层的解释，但不得剔除长帧后只交“顺滑段”；只按已冻结暂停/无效相位规则分离无效窗口。沿用T76单目标稳态模块开销两段连续120个有效帧p95>0.5ms即失败、稳态分配/对象材料持续增长即失败。若新增模块使总体长帧或体验明显恶化，即使未撞0.5ms线也拒绝该候选并定位；不能用独立已知项豁免新回归。真实UI/枪声/保存保护也不得因性能实验退化。

该独立项后续需要：同场景模块OFF/ON真实Profiler或等价CPU/GPU/GC时间线，按长帧关联；目前只登记观察和取证需求，不凭均值FPS生成性能修复票内容，更不把长帧解决作为等待G启动的前置任务。
