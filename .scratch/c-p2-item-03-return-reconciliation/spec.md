# C-P2-Item-03 实施规格

## Problem / Solution

返区不能收到无人期间已过期物资，也不能多观察者重复抽货。以区域为单位完成一次当前结果结算，完成前阻止清单、模型和拾取消费半完成状态。

## Fixed inputs

用户2026-10-08批准本票不拆；依赖02及其01前置记录。研究插件 `57e3c4e4411b4f8831f0bf6d489b9fea9922c47c`，SDK `ea7b4973af5ba10f62baad2bfde36ab2e5b060eb`。读 [共同输入](../item-migration-slice/execution-inputs.md)、[主规格](../item-migration-slice/spec.md)、[原生衔接事实](../item-migration-slice/native-integration-flow.md) 及ADR0020、0026、0027。

## Implementation decisions

- 共享有效需求启动本次区域作业，同期只允许一个；后来者登记等待同一结果。需求与租约分离，滞回内重入也不能漏掉业务恢复。
- 先清全部过期自然项，后按原生资格尝试当前缺量；不回放无人期间随机批次，不因进区无条件补满。保留旧存活年龄，新项从实际创建计龄。
- 原生despawn一调用至多删一项，respawn bool不证明创建；按实际数据/计时结果推进，不重做已提交动作。
- 本轮补货阶段确定有限尝试预算；每次创建检查当前数量/占位，包含实际掉落及本轮新项。失败点消耗尝试、允许未补满；达到目标可停止，不能因新观察者/分帧/掉落到期重开预算。
- 大作业分帧，所有Item区域共享有限总帧预算；玩家继续走动。正常准备、等待或模型分帧不是失败，不套10秒期限或手动重试。
- 完成门同时覆盖原生区域清单、自然新增增量、Host本地实例化及背包写入前的拾取就绪检查；不能只挡askItems。原生成功写背包后才删除地面物品的顺序保持。
- 同区不并行启动其他自然周期；实际掉落仍写同一权威仓库并从实际出生计龄、独立到期，不能被旧列表覆盖。
- 完成后自动向仍有效等待者发送当时权威清单，不要求再移动触发step5；校验当前会话/连接/需求，离开者不发。清单已涵盖的历史变化不额外回放，删除沿用instanceID取消待实例化，避免重复或复活。
- 最后需求离开仍有限收尾，不暂停/撤销/重复删除补货；无等待者不发清单，完成立即休眠。收尾中重入等同次结果，完成后新需求从收尾后的状态重判。
- 正常Release/覆盖补偿不回滚权威变化；会话、地图或区域身份失效隔离旧作业。异常保留已执行结果与不可用状态供04恢复，不盲目重跑；本票不实现重试状态机。

## Testing decisions

- 用真实高层入口/共享引擎，薄边界控制时间、动作及发送。沿用01/02fixture，检查数据、动作次数、呈现/拾取许可和基线顺序。
- Red覆盖旧项先删除、当前缺量失败、后来者同次等待、跨帧超过10秒不误报、Host/Guest完成前禁止消费、完成后不移动也交付。
- 覆盖最后需求离开/收尾重入/完成再返区、旧身份隔离、实际掉落并发创建和到期、完成清单无重复/复活、多区域总预算有界。
- 验证请求被就绪门拒绝时不写背包、不删地面；距离校验另由07验证。StaticIL核对真实增量/本地模型/拾取入口，PureMemory不冒充客户端效果。

## Out of scope / Deliverable

不实现异常重试/命令、旧Writer正式退役、20米校验或其他域。交付完整结算到呈现垂直行为、Red/Green/回归及绑定证据；不能以只做算法或只做账本满足本票。
