# 需求规格说明书：Join Routing

## 问题陈述

客机在直连页粘贴 `SteamID:27016` 时，插件把整串当原版地址，连接静默失败。房主即使想设房间密码，开房流程也把服务器密码固定写成空；SteamID 路线又把客机密码硬编码成空串。玩家看到的是「带端口的 SteamID 连不上」和「密码房间对 SteamID 无效」，而 IPv4 直连路径已经会读密码。

这发生在进入世界之前，与 Route B Quarantine（进世界后的 30 秒软隔离）不是同一件事。旧仓「审核机制 / 排队无响应」也不是这件事。

## 解决方案

把 Join Routing 做成一个小产品切片：房主在开房菜单为当前 listen-host session 提供可选密码；客机 SteamID 路线把直连页密码传入连接参数；分类器在判断个人 SteamID 之前剥掉合法的单个 `:port`。无密码房间保持现在能进的行为。密码错误继续由原版产生 `PASSWORD`。密码不落盘、不进审计、不进普通诊断明文。

## 用户故事

1. 作为房主，我想在开房菜单留空密码，以便房间和现在一样谁都能进。
2. 作为房主，我想在开房菜单填写密码，以便只有知道密码的客机从 SteamID 路线进来。
3. 作为房主，我不想密码被写进上次房间设置或配置文件，以便换机或分享配置不会泄露。
4. 作为房主，我想结束会话或回菜单后密码从运行时消失，以便下一局不会沿用上一局密码。
5. 作为客机，我想在直连页 SteamID 栏不填密码就加入无密码房间。
6. 作为客机，我想在有密码房间不填或填错密码时看到原版密码失败，而不是插件自己的第二块提示。
7. 作为客机，我想填对密码后从 SteamID 路线进入有密码房间。
8. 作为客机，我想粘贴 `SteamID:27016` 仍按 Steam P2P 连接，以便从聊天复制「ID 加端口」不再静默失败。
9. 作为客机，我不想 `192.168.1.1:27016` 或域名被当成 SteamID。
10. 作为客机，我不想 IPv6 或多冒号地址被「最后一个冒号」规则切坏。
11. 作为维护者，我想日志只出现 `hasPassword=true/false`、路由种类和失败枚举，以便诊断时不泄露密码。
12. 作为单机或未开 P2P 的玩家，我不想直连页原版密码框的行为被改掉。

## 实现决策

- 分类契约（在判断个人 SteamID 之前）：输入形如 `[可选空白] SteamID [可选单个 :port] [可选空白]`。仅当同时满足才返回 Steam P2P：冒号最多一次；冒号后是十进制端口；端口 1–65535；去掉端口后剩余部分是合法个人 SteamID。分类只使用 SteamID；随后的 P2P 连接参数不使用该端口。禁止「最后一个冒号」切割。下列不得判为 Steam P2P：IPv4:port、DNS:port、`:0`、`:65536`、非数字后缀、多冒号（含 IPv6）。这些继续走现有 Direct-IP / DNS / Vanilla。
- 房主密码来源：插件开房菜单新增字段，默认空，密码遮罩，`MaxLength` 与原版直连页一致（不设上限），不 trim。空串 = 无密码房间。非空值只写入当前会话的服务器密码。输入规则只约束这个新字段，不改变原版直连页密码框。
- 生命周期：返回菜单、结束会话或销毁房间时清空运行时密码。不写入上次房间设置、审计报告、普通诊断日志或仓库文件。日志与诊断快照只记录 `hasPassword`，不记录明文、不记录长度、不把连接参数里的密码打出来。
- 客机 SteamID 路线从原版直连页密码框读取并传入连接参数。IPv4/DNS 已有的密码传递保持。
- 失败呈现：不改写 `connectionFailureInfo`，不把 `PASSWORD` 转成自定义失败类型，不拦截原版失败面板，不新增专门密码弹窗。现有通用连接失败提示若保留，只记录失败枚举。
- 不触及 Route B Quarantine、白名单开关、Direct-IP 丢 advertisement、IPv6 支持。

## 测试决策

好测试断言分类结果、是否携带密码、会话清空和失败枚举，不断言 UI 控件坐标。

- PureMemory：上表每条分类输入；无密码 / 有密码参数组装（断言 hasPassword，禁止读明文）；会话结束后运行时密码为空。先例是地址分类器的纯函数测试（若尚无，按同一 Evidence Class 新增）。
- StaticIL：仅当实现以 Harmony 改分类或连接按钮时，才锁替换次数；纯函数改分类器则以 PureMemory 为主。
- BuildArtifact：Runtime 三端 SHA-256 一致。
- Runtime（与 Dedicated Gate 共享一次 1 Host + 2 Guest）：无密码房间不填密码可连；有密码房间不填密码由原版产生 `PASSWORD`；填对密码可连；地址栏 `SteamID:27016` 走 Steam P2P 连上。日志只证明 hasPassword、路由类型和失败枚举。

## 范围外

- Route B fail-open、隔离建立过晚、白名单中途关闭。
- 直连/DNS 补 A2S advertisement、IPv6。
- 把密码持久化进房间设置或 Steam 云。
- 覆盖原版失败 UI。
- Dedicated Gate、Collision 迁移。
- 旧仓 GitHub #1/#2 的握手超时回归（仅当 0.2.4 再出现 `TIMED_OUT_LOGIN` 才另立）。
