# C-P2-Item-07 权威拾取距离实施规格

状态：2026-10-08用户批准独立实施票；无空间迁移前置依赖，尚未实现。

## Problem Statement

U3DS在原生拾取请求中检查玩家到权威物品位置的距离；listen-host跳过dedicated分支。本次恢复这条已有校验，按Q14单列工作。

## Solution

在listen-host权威拾取入口复用U3DS原生20米限制，超距请求不写背包、不删除地面物品；正常操作仍走原生拾取事务。

## User Stories

1. 作为玩家，我希望正常拾取保持原有操作方式，以免恢复权威校验改变交互距离。
2. 作为房主，我希望远处物品不能被超距请求取走，以免租约或客户端请求绕过原生限制。
3. 作为玩家，我希望被拒绝的拾取不丢失地面物品，以免失败请求造成物资损失。
4. 作为玩家，我希望距离合法后仍检查背包容量和其他原生条件，以免本项校验错误地授予拾取权限。
5. 作为维护者，我希望此任务有独立验收结果，以免生命周期或同步通过掩盖交互校验缺失。

## Implementation Decisions

- 仅在SPF有效P2P listen-host权威会话启用；普通单机、Guest客户端自身及原生U3DS路径保持原有行为。
- 使用请求实际调用玩家位置和目标instanceID对应的权威ItemData位置；复用原生距离平方大于400的拒绝条件，不增加新可调距离、不依赖客户端报来的物品坐标。
- 在原生背包写入之前检查；超距不加背包、不删地面物品，正常通过后仍执行原生身份/存活/姿态/实例/扩展回调及背包成功后删除的事务顺序。
- Host与Guest发起的请求均按权威入口处理；不改变正常拾取操作范围、视觉或物理，不新增视线/穿墙检查，不全局改dedicated。
- 与区域结算就绪校验并列；租约不授权拾取。此任务可在现有仓库上独立验证，不以完成生命周期/同步迁移为前置，也不替那些票验收。

## Testing Decisions — 2026-10-08用户已确认独立入口

测试生产拾取请求校验入口，观察是否调用原生背包/地面写入路径；fake仅替代原生玩家/仓库动作边界，不只测试一个孤立距离公式。用户确认此入口验证一次请求能否写背包，与区域准备/结算/清单入口分别验收。

- 距离平方400不被本项拒绝，略大于400被拒绝；通过距离仍可因背包满、死亡或原生回调等其他条件失败。
- Host/Guest来源分别验证；超距时背包与地面物品均无新增/删除，同区有租约也不能绕过。
- 静态绑定/注册证明实际原生请求路径消费校验；部署后运行分别验证正常拾取及受控超距请求，未执行时不报告PASS。
- 与生命周期/同步分别记验收结果；最终交付不能用任一条线的通过代替另一条线。

- 以实际生产请求校验入口写Red再Green，不只验证距离公式；使用可控原生动作薄边界确认拒绝前无背包/地面副作用。
- 实机正常拾取与受控超距请求必须到达真实权威入口；记录实际请求/权威位置及拒绝效果，不能用普通客户端无法选中远处物品当作校验已通过。未取得对应证据保持OPEN。
- 运行可与06同轮采集，但保存07独立结论；没有空间迁移或06通过不阻止本票独立验证，07通过也不关闭06。
