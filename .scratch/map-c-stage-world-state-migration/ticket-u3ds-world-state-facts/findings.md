# 原生世界状态调查索引与迁移讨论入口

日期：2026-10-07。首轮源码调查文档；正式复核状态见 [审查链](review-chain.md)，不是冻结实施规格。

## 调查目的与证据

按照用户裁定，先理解 U3DS 原生实现，再讨论避免哪些全图运行成本、哪些职责迁入 multi-observer；Item 是迁移起点。本轮不冻结运行政策或实施票。

固定插件 HEAD、SDK HEAD、引用 DLL 哈希及版本对照限制见 [共享控制面与调查基线](findings-control-plane.md)。所有结论是源码事实或具名推断；没有新构建、性能测量或实机 PASS。

## 核心发现

U3DS 没有一个统一的“全图保活逻辑”。状态仓库、计时轮询、AI 活动子集、组件 Update、碰撞/渲染激活、基线与增量收件人分别有自己的门。迁移必须逐项判断，不能只见 Dedicated 分支或全局列表就整体替换。

## 两项先前示例的纠正

- 原生已经有 Item 拾取删除和掉落增量。迁移应调查与共享控制面的关系，不以“新适配器没有拥有它”推导“当前不存在该功能”。
- 当前会话重连与关房重开是不同场景。核心保存链没有地面 ItemData 恢复入口；不能把地面掉落跨会话保留直接写进 U3DS 等价性验收。依据 Item/全局报告事实 21–26。

## 候选职责分界（建议，未裁定）

1. 继续复用原生权威数据、合法交互、资产语义与原生保存格式，避免建立第二世界仓库。
2. 将需要改变的观察者空间需求、运行授权、插件执行覆盖、逐观察者复制资格与恢复纳入共享控制面；不是把所有原生循环都搬入租约。
3. 对全局时钟、轻量计时扫描和无人生产分别选择保留执行或等价恢复策略，先说明玩家可见结果与成本，再决定实现。
4. 当前 SPF 原生同步迁移复用已有游戏协议，不因上层功能模组频道规则而强制接入 LMN；后续范围纠正见 [0021: SPF 原生世界同步迁移不自动成为 LMN 消费方](../../../docs/adr/0021-spf-native-world-sync-and-gameplay-mod-channel-boundary.md)。

## 下一轮问询的事实例子

- 两客机远区砍树/拾取、各自离开再回：区分世界物品数据与客户端模型。
- 玩家第一次抵达城镇：按需首次生成与原生 U3DS 加载时生成具有不同计时/随机历史。
- 无人在基地时发电机扣油、作物成熟及雨桶接雨：停用整个组件可能改变计时或天气遮挡事件。
- 玩家离开动物群或无人车：原生 Pack/实体状态不能仅凭二维 Region Release 销毁。
- 区域最后一人离开，但 Beacon/车辆乘客/全局天气仍在进行：普通空间需求不覆盖所有运行理由。

## 本轮覆盖界限

完成的是 manager、关键实体和代表性生产组件的首轮事实地图，详细未查项分别保留在三份分报告末尾。未穷尽每种工事/任务/地图脚本、全部 Unity active 与物理入口、驾驶输入链、P2P 保存路由和网络乱序恢复。它们须随前沿决策进一步调查。

本轮只关闭事实收集的首轮阶段，不证明所有剩余功能已盘点完毕，也不决定 Item 之后的顺序。实施 Red/Green 与运行验收仍有 `GAP-C-P2-IMPLEMENTATION-TDD`，由冻结后的实施票承接。
