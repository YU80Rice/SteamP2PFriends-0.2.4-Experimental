# Item Migration Slice 实施规格

状态：2026-10-08用户批准玩法、两条独立测试入口、七票粒度/依赖及工程默认值；作为各独立实施票的共同固定输入。规格批准不代表实现或运行验收通过。

## Problem Statement

客机远离房主时，物资仍应正确存在、被拾取和刷新。当前 Item 主要靠原生进区补丁运行，尚未复用共享观察者与生命周期引擎；全图巡检仍能提前刷新未访问区域，基线拒绝也不保证自动恢复。仅有账本测试不能证明实际生产路径或客户端模型正确。

## Solution

先完成全图自然物品数据准备，再开放相应 Item 联机运行。首次领域需求启动该区域自然计时；有人需求时按原生规则运行，无人时停止实时自然周期。返区先清过期自然物资，再按原生资格尝试补当前缺量，新补物品从本次生成时计时。实际掉落物独立到期清理。

观察者事实、领域需求和生命周期编排使用已验证的共享引擎；原生仓库、区域清单、增量、模型呈现和交互继续复用。正常进区自动呈现，不要求每区完整 ACK/模型齐全。未就绪/失败时局部有界恢复，明确提示并允许重试。

## User Stories

1. 作为房主，我希望全图物品数据准备完成后才开放相应联机运行，以免客机遇到半准备状态。
2. 作为玩家，我希望第一次靠近区域看到已准备的物资，以免每次进区重新抽取整区物品。
3. 作为玩家，我希望未访问区域的自然周期尚未启动，以免首次到访物资已经历无人的消失/刷新。
4. 作为玩家，我希望仍存活的旧物资保留年龄，以免反复进出重置寿命。
5. 作为玩家，我希望返区先清旧过期物资，再按规则尝试补货，以免旧物与新物叠加。
6. 作为玩家，我希望自然补货仍受时间、数量、点位和生成表约束，以免进区就无限补满。
7. 作为房主，我希望无人区域停止实时自然周期，以降低持续处理成本。
8. 作为玩家，我希望无人期间的实际掉落物仍会到期，以免地面成为永久垃圾场。
9. 作为玩家，我希望拾取失败不减少地面物品，拾取成功只进一次背包，以免丢失或复制物品。
10. 作为两位同区客机，我希望各自收到基线，而世界只启计/结算一次，以免相互刷新或拆除物资。
11. 作为留在区域的玩家，我希望另一人离开不停止我所在区域的自然周期，以免多人需求互相覆盖。
12. 作为正常游玩的玩家，我希望继续走动、看见物品就按原生拾取，以免每区都出现新等待流程。
13. 作为遇到异常的玩家，我希望只有受影响物资暂不可用并可恢复，以免一个区域失败停掉整房间。
14. 作为重连玩家，我希望旧连接的恢复操作不能污染新连接，以免重复基线或错误删除。
15. 作为换图玩家，我希望上一地图的计时/来源/待恢复记录失效，以免旧状态进入新会话。
16. 作为普通单机、Guest 或 U3DS 使用者，我希望 SPF 新政策不改原生运行路径，以免全局伪造 dedicated 破坏形态。
17. 作为维护者，我希望新路径确实消费共享控制面，以免新增空 SPI 类型和无关单测再次冒充迁移完成。
18. 作为结算期间进入的玩家，我希望等待该区域正在进行的同一次结果，以免并列重算或先收到旧物资；大批量结算时仍可走动，完成后自动呈现并允许拾取。

## Implementation Decisions

### 权威与共享控制面

- Native State Authority 继续持有 ItemData；只旁挂来源、准备/启计/结算状态、计时基准和身份元数据，不建立第二物品仓库。
- Item 声明自身 Demand Policy，空间形状和范围读取原生 Item 区域策略；共享 Observer Spatial Authority 是唯一观察者事实来源，含 Host 与既有 World Presence Observer。
- Item 注册 Production Control Seam / Domain Execution Port，复用 Demand Projection Engine 和 Lifecycle Orchestration Engine；不复制客户端扫描、通用滞回/重试状态机，不新增领域 switch。
- Session Epoch/Connection Generation 消费 Core 唯一来源；原生区域重建身份、初次生成标记和一次物品变化不能混成同一个 generation。
- Gameplay Authorization 与空间需求分离，保留既有审批/隔离和原生合法交互校验；租约不授权拾取。

### 准备、来源与计时

- 原生数组/地图物资点/资产输入可用后，执行全图一次准备；合法空区域也提交就绪。不能用服务端已打开、房间已发布或 Host 活动作为 Item Preparation Readiness。
- 不盲目复活旧全图补丁，也不在 Core 会话绑定时清空/二次生成本轮已准备数据。准备记录须绑定实际地图输入与本轮会话，迟到回调不得被下一轮收养。
- 自然物品来自首次生成/周期刷新创建路径，实际掉落来自掉落路径；不能只用isDropped判来源。Q11已决定到期分类对齐U3DS：自然物品用Despawn_Natural_Time，玩家丢弃及已核实僵尸/动物/资源实际掉落用Despawn_Dropped_Time，不保留listen-host的上述配置差异，不把全部地面物品统一改旗。
- 扩展回调中嵌套实际掉落仍属实际掉落，不得误计为自然物品或因首次自然列表替换而丢失；直接未知来源不得自动获得自然休眠资格。
- 首次需求只为本轮预生成自然物品建立有效计时起点，并建立自然刷新起点；实际掉落计时不整体偏移。Item 时钟使用对应原生单调时间，保留配置和原生阈值语义，不使用现实日期或 Provider.time 混算。
- 数据准备、首次启计、返区结算和基线尝试是不同状态；多个观察者或重试不得重复完成已成功的业务动作。

### 有需求、休眠与返区

- 自然实时周期只在本域存在有效需求时执行，需求来自共享投影；释放滞回保留租约的行为不暂停玩法时间。物品数据和已启动计时不随 Release 删除/归零。
- 实际掉落到期资格与区域首次访问、自然周期和租约独立；到期调度有界推进，保留原生配置/模式例外，不承诺毫秒级阈值瞬间删除。
- 返区只结算当前结果，不回放无人期间每批随机物资；先确认过期自然项已排除，再在原生刷新资格满足时执行当前缺量尝试。新补项从本次生成计时，存活旧项不归零。
- 复用原生数量、抽表、占位、安全区及扩展资格；数量/占位包含实际掉落和本轮新项，失败尝试允许未补满。首次生成与周期刷新的原生算法差异保留。
- 不将“despawn 返回 true”当作过期已清完，也不将“respawn 返回 true”当作实际创建成功；薄边界记录实际对象/无变化、计时变化及失败结果。
- Q12已决：每次返区结算按区域共用一次，由首个有效需求启动；结算期间其他观察者只登记等待该次结果，不并列重算或额外抽取。大量物资分帧推进，完成前不发区域清单，Host本地模型/拾取也不能消费半结算的旧状态；玩家继续走动，完成后自动呈现。
- 正常结算进行中、等待同次结果及正常模型分帧均非异常，不消耗异常重试次数/期限，不触发失败提示或手动重试。
- Q13已决：当前会话/区域有效时，最后有效需求离开也继续分帧收尾已启动的这一轮，不暂停、不撤销、不重做已执行删除/补货；无等待者不发清单，完成后立即休眠，不再启动自然周期。已执行物资变化就是权威结果；下次需求从收尾后的状态重新判断，收尾中重入仍等同一次结果。换图/会话或区域身份失效时不继续操作旧仓库。
- 在返区本地模型/远端基线消费状态前完成相应结算；追加观察者只取得当前基线，不触发整区重生成或额外回放。发送失败后的重试不重新抽取已成功结算的物资。
- 不要求 Host 实例化所有远端区域物品模型；本地模型/物理沿用对应原生路径与其他领域能力，不以 Item 租约授予 Collision/Resource 覆盖。

### 结算期间的原生动作与同步衔接

- 结算由共享有效需求变化驱动，不能只靠Acquire/Release或“租约仍存在”判断是否有人需要；区域业务进度与观察者订阅/租约资格分开，正常Release不删除Q13允许收尾的业务作业。
- 已启动结算同区不并行执行另一轮自然周期；所有Item区域作业共享有限帧处理预算，实际掉落创建/到期仍独立运行。成功写入的实际掉落从实际产生时计龄，不等结算完成才开始，也不被旧列表覆盖。
- 补货阶段使用当前仓库确定本轮有限缺量/尝试预算；每次创建前核对当前数量/占位（含实际掉落及本轮新项），达到目标可停止余下补货。分帧、后来者或掉落到期不重开/扩张该次尝试预算，失败尝试不保证补满。
- 原生自然刷新同时写数据并发新增包，接线必须阻止结算增量/Host本地实例化绕过完成门，不能只挡区域清单。结算未完成时，拾取就绪校验位于背包写入之前；成功后才删地面物品的原生顺序保留。
- 完成后，对仍有效等待者按原生路径发送当时权威仓库清单，并衔接正常增量；结算期间已被当前清单涵盖的新增/删除不再另行回放。尚未呈现就已删除的物品不能事后复活，沿用原生instanceID取消待实例化能力。
- 完成驱动后续交付，不要求玩家再走一步触发step5，也不阻塞其他域区域更新。发送前核对当前身份/需求，离开的观察者不发，重连不能继承旧资格；订阅/覆盖补偿不得撤销已执行删除和补货。
- 实际异常恢复前核对已执行原生结果，只推进确认尚未完成的步骤；无法确认时保留不可用状态并报异常，不盲目整区重跑或复制物资。

### 原生复制、恢复与切换

- 继续使用原生区域基线、新增/删除增量、拾取/掉落事务及本地实例化；当前切片不强制 LMN、新通用路由器或完整基线 ACK 协议。
- 每观察者基线资格/连接身份分别处理；loaded bit 是原生投影，不替代权威准备/结算状态。正常 Prefix 拒绝须有恢复资格，不能只回滚 bit 后让 step 永久推进。
- 常规主线程/可靠 lane 顺序保留；发送调用返回、可靠标志、实际入队、数据接收与模型出现分别记证据，不能用 capability 名称冒充完成。
- 受控恢复不得盲目对已 networked 或可能半包区域重发清单；用户已选择原生离区/返区清理路径，当前不新增原地reset双端接线。只有明确尚未开始交付的失败可在当前区域重试基线；不能把void发送返回当作“肯定没发”。
- 耗尽后复用原生定向聊天提示和用户专用聊天重试指令；主机验证当前审批/会话/连接/相关失败区域及预算，不开放管理员命令。可能半包时说明须离开该区域物品加载范围再回来；原生离区取消队列/清networked及loaded，返区是新需求的正常尝试，不延续旧恢复资格或重新抽物资。
- 自动恢复有次数/期限上限，达到上限后进入可见局部失败状态，用户可发起受身份验证的重试。共享政策扩展须保留 Resource/Collision 默认语义；quietAttempts 不能代替次数上限。
- 初次准备失败不得标记全图成功或开放依赖该准备的 Item 正常运行；运行中权威区域失败影响依赖该数据者，单观察者发送失败只影响该观察者。运行中局部失败不停止无关域/区域，不扩成全房间停机。
- 新插件侧 Item Authority Writer 在会话边界选定，禁止同一会话双写、分玩家切换或失败回退旧 Writer。迭代中的未完整候选不部署作正式体验。
- 旧 M1/M2 资格投影和 P2P 全图周期调度退出权威调用链；原生算法及对 SP/Guest/U3DS 的 passthrough 不作为旧 Writer 删除。验证旧生产路径实际不再驱动，不能仅删类名。

### 已批准的工程默认值

2026-10-08用户批准以下默认值；各票不得自行漂移。

- Item 租约释放滞回 2 秒；自然周期资格仍跟随本域需求，计时继续推进，短暂重入不重复首次启计。
- 已检测失败的单次恢复链首次尝试＋最多3次自动重试、最多10秒（先到者），重试间隔0.5/1/2秒；不对正常权威结算、等待同次结果或原生模型分帧套用该失败期限。
- 失败提示去重，同观察者/区域每10秒最多接受一次用户恢复请求；离区、断线、代次变化和会话结束使旧恢复资格失效。
- 用户重试通过原生聊天命令 `/spfitemretry` 到达主机控制入口，不能只清客机缓存；沿用原生聊天频率限制并隐藏操作文本。可能半包时沿用离区返区方式，不引入LMN或新UI。

恢复链从首次已检测的实际异常起计，重复回调不重新创建预算以绕过上限；正常准备/结算进行中属于等待进度，不因尚未完成而启动失败预算。离区/断线撤销旧观察者恢复资格，但有效会话/区域中的已启动结算按Q13继续收尾；会话/区域身份失效则隔离旧工作。原生模型逐步呈现、未有故障证据的正常传输，不直接被判作失败。

## Testing Decisions

### 生命周期/同步行为测试入口（2026-10-08用户已确认）

用户确认本入口验证区域准备、结算及清单发送；20米拾取校验另走独立权威请求入口。租约不能代替距离校验，两条线分别验收，任何一条通过均不能替另一条关单。

以一个高层生产入口贯穿“准备 → 共享观察者需求 → Item 原生执行边界 → 基线/恢复效果”。使用真实共享投影/生命周期引擎和真实 Item 业务政策，注入可控时间、原生状态/动作边界及发送结果；fake 只替代 Unity/网络/原生动作，不替代要验证的生产逻辑。

优先沿用共享引擎及 Resource 生产接缝的 fixture 方式，并复用现有 Item 一次生成/复制事务的行为先例。避免新增第二纯内存 Item 仓库作为生产实现，避免孤立 ledger 全绿却无生产调用。

核心可观察用例：

1. 全图含空区只准备一次，提前请求未开放；Core 会话绑定不清掉同轮已准备数据。
2. 初次需求自然启计，实际掉落年龄不改；第二观察者不重复生成/启计，并获得独立原生基线。
3. 一人离开不停止另一人需求；零需求停止自然实时周期，实际掉落在未访问/无人区继续到期。
4. 原生配置阈值与有效计时基准正确；首次进入不因数据早已创建而立即过期，存活旧物返区不归零。
5. 返区全部过期自然项先被排除，再按资格尝试当前缺量，再交付本地模型/远端基线；失败尝试不要求补满。跨多帧执行时后来者等待同次结果，完成前各端不先取得旧清单/拾取，正常分帧不进入失败预算，即使超过异常期限也不误报。
6. 生成回调内嵌实际掉落不误分类/不丢失；来源未知不按可休眠自然项处理。自然与实际掉落期限配置设成不同值，验证已核实原生来源按U3DS分类到期，未知来源不被统一改旗。
7. 实际已完成的创建/删除/计时结果在同步重试中不重复提交，不因每个观察者多做一次随机结算。
8. 正常拒绝/异常有恢复链，达到预算停自动尝试并可手动恢复；重复帧回调不绕限，旧连接/区域/会话不能重试。
9. 可能半包时不在已networked区域盲目追加，提示/用户重试/原生离区清理/返区基线闭环；未发送前拒绝可当前区域重试。正常原生分帧模型无新增全区 ACK 门。
10. SP/Guest/U3DS 与原生模式例外 passthrough；Resource/Collision 的已有需求、重试/Release 和形态无回归。
11. 结算中最后需求离开仍分帧完成，删除/补货不回滚或重做，无等待者不发清单，完成后无下一轮自然周期；收尾中重入等同次结果，完成后返区重新判断。换图/会话失效不继续操作旧仓库。
12. 分帧期间新增实际掉落进入同一权威仓库并独立计龄/到期，参与补货数量/占位；创建或删除后完成基线不重复追加/复活，尝试预算不重开。未就绪拾取不写背包；完成后玩家不移动也能得到基线，多区域总处理预算有界。

### 证据边界

- PureMemory 验证上述高层行为和身份/预算，不证明原生 IL、实际 packet 或模型效果。
- StaticIL/编译绑定验证真实准备回调、原生方法签名、注册、共享引擎消费与旧 Writer 退役；仅有类型存在不通过。
- BuildArtifact 使用可复现版本/指纹，并独立复核实际部署产物；本阶段不构建或授予新身份。
- Runtime 固定 1 Host + 2 Guest：远离 Host 首次到访/返区、双 Guest 同区与各自离开、实际掉落到期、多人争拾/背包满、重连/换图、至少一个可控局部失败恢复、多包基线及 Host 本地回归。日志同时绑定主机权威数据、各端呈现/交互和 Writer 路径。
- Runtime 使用临时明确配置/可复现实例缩短计时，记录原配置并恢复；不得以纯内存或 StaticIL 代替运行验收。完整切片测试不能仅用 1H1G 顶替三端。

2026-10-08用户接受三端最终验收安排。开发与问题定位可先用较少端数；最终用两位远端观察者验证共用结算、独立清单、需求聚合与故障隔离。Host本地路径不能替代第二条远端复制路径；20米校验另记结果。

## Out of Scope
