# C-P2-Item-06 人工验收规格

## Problem / Solution

内存测试、原生绑定和构建不能证明三端物品呈现/交互正确。对05完整单Writer候选运行实际多人剧本，分析证据后由用户决定是否关闭本迁移线。

## Fixed inputs / Preconditions

- 用户2026-10-08批准三端形态及独立记录；依赖05完整候选、实现验证/审查记录与可复现构建身份。
- 研究插件 `57e3c4e4411b4f8831f0bf6d489b9fea9922c47c`，SDK `ea7b4973af5ba10f62baad2bfde36ab2e5b060eb`；运行必须使用05实际最终候选身份，不能拿研究HEAD冒充DLL身份。
- 必读 [共同输入](../item-migration-slice/execution-inputs.md)、[主规格](../item-migration-slice/spec.md)、[实机循环](../../docs/agents/real-machine-test-loop.md)、[部署/采证SOP](../../docs/agents/auto-rm-test-sop.md)。
- 用户部署候选并核对三端指纹，经UMM启动、执行并导出每端诊断包；Agent不得伪造人工执行或采集结果。

## Runtime cases

1. Host正常首访/本地呈现和拾取；Guest1远离Host首次进入双方未访问区域，看到预生成物资并能正常拾取。
2. Guest1/Guest2同区，首次自然计时及返区作业只一次，各自获得清单；一人离开另一人仍有需求；三端分散各自正常。
3. 用明确临时配置缩短自然/掉落期限，记录并最终恢复原配置；无人自然停实时周期，实际掉落独立到期，返区当前结果符合原生资格。
4. 大区分帧结算，Guest2途中加入等同次结果；完成前无旧清单/模型/拾取，玩家继续走动，正常长等待无异常提示；完成后不移动也交付。
5. 结算期间所有需求离开，本轮仍收尾，无等待者不发清单，完成后立即休眠；收尾中重入/完成后返区不回滚或重做。
6. 分帧中产生/到期实际掉落，补货数量/占位按当前仓库；多包清单和增量不重复、不复活已删除物品，原生待实例化取消正确。
7. 两Guest争拾同一物品，最多一次成功；背包满等失败不删地面。此项验证原生事务，不代替07超距校验。
8. 可控实际局部故障触发有限重试/耗尽提示；`/spfitemretry`身份/10秒频控有效，另一Guest及无关域继续工作。可能半包沿完整Item加载范围离区返区恢复。
9. Guest断线重连、会话/换图隔离旧身份与恢复资格；旧Writer不驱动，Resource/Collision及Host音画/本地操作无回归。

## Evidence and verdict

- 每例记录环境、动作、预期、实际、三端日志锚点、Case-ID及候选SHA-256/MVID；同时核对Host权威数据、各端呈现/交互和Writer路径。
- 可靠标志/发送返回不是送达或模型出现；缺日志/未执行/不可判读记OPEN，不把PureMemory或StaticIL通过提升为Runtime PASS。
- 异常回到责任实施票按仓库修复/审查/候选身份流程推进，不在验收票顺手改业务；新候选须重新绑定实际部署身份。
- 06可与07同轮采证，但写独立验收记录/逐项结论。一条线通过不能给另一条关单；07不作为本票阻塞边。
- 报告使用仓库ticket-bearing audit路径并登记索引；用户人工裁决关单/发布，其他C阶段地图不关闭。
