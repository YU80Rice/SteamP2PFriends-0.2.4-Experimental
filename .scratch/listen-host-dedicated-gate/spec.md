# 需求规格说明书：Listen-Host Dedicated Gate

## 问题陈述

房主用插件开 P2P 房间后，客机可以进来砍树、走动，但世界不会按专用服那样继续活着。僵尸被打死后不再出现；地上的东西不会按服务器节奏消失，也不会再长出来。旧仓玩家把这说成「只刷新一次，要重进才有」。

根因不是 Multi-Observer 没铺到僵尸域或物品域。原版把周期重生和物品生命周期放在 dedicated 早退后面：听主机不是专用服，这段逻辑根本不跑。已有补丁已经把若干状态广播门控换成 `IsDedicatedOrP2PHost()`，但 `respawnZombies` 的早退和 `ItemManager` 更新里整段 despawn/respawn 早退还对着 `IsDedicatedServer`。

## 解决方案

只打开 Listen-Host Dedicated Gate：让听主机在这两处早退上与专用服走同一分支。不改僵尸怎么生成、信标怎么计数、Horde 怎么出波，也不改物品怎么从生成表里抽。进世界时已有的一次性预生成保留；周期处理负责之后的服务器语义。若运行时证明两套机制把同一区域刷满，另开收缩票，本规格不预先拆掉预生成。

## 用户故事

1. 作为房主，我想在 P2P 房间里打死一只普通僵尸后过一会儿再看到新的僵尸，以便不用重开房间。
2. 作为客机，我想在远离房主的区域清完一波后世界仍会补怪，以便探索不是一次性的。
3. 作为房主，我想地上过期的物品会消失，以便听主机不会变成永久垃圾场。
4. 作为客机，我想物资点在周期之后再长出东西，以便「只刷新一次」不再发生。
5. 作为单机玩家（未开 P2P），我不想普通单人世界突然按专用服刷怪和刷物品，以便单机节奏不被插件改掉。
6. 作为在 Horde 图上的房主，我不想这次修复改掉波次逻辑，以便灯塔防守仍按原版。
7. 作为点燃导航信标的房主，我不想信标剩余计数和补怪规则被这次修复改掉。
8. 作为测试人员，我想从诊断里看到听主机走进了与专用服对齐的早退分支，以及 `generateItems` / `despawnItems` / 周期 respawn 的次数和区域，以便区分「还在等重生窗口」和「早退仍在」。
9. 作为测试人员，我不想一次三端测试里既要换 Horde 图又要召信标，以便用普通 PEI 就能验收主路径。
10. 作为维护者，我不想本票去改全量僵尸 tick 切片或把僵尸域接到 SpatialObserverIndex，以便性能问题和域迁移仍是独立工作。

## 实现决策

- 唯一生产接缝是现有的 `IsDedicatedOrP2PHost()`。禁止新造第二个听主机资格函数，禁止全局伪造 `IsDedicatedServer`。
- 僵尸：只替换 `respawnZombies` 里「非 dedicated 且无 Beacon、非 Horde 则 return」所依赖的资格判断，使其在听主机上进入原版专用服重生分支。不修改生成表抽取、特化、Boss 上限、信标剩余、Horde 波次、`respawnZombiesBound` 轮转、tick 调度，也不再次修改已经对齐过的 `SendZombieStates` 门控。
- 物品：只替换更新循环里整段 despawn/respawn 的 dedicated 早退，使听主机继续执行周期移除与再生。`onLevelLoaded` 一次性预生成保留。禁止在本规格内关闭、缩小或重写预生成。
- 诊断必须能按区域计数：`respawnZombies` 是否走进对齐后的分支；`generateItems`、`despawnItems`、周期 respawn 的调用次数与区域。诊断不得成为第二套生成器。
- 普通单机、客机、菜单保持原版早退（资格函数为假）。专用服行为不变。
- 不把 Collision 覆盖集、Join Routing、Route B Quarantine 或白名单开关放进本规格。

## 测试决策

好测试只断言资格与外部行为，不断言具体 IL 指令序列之外的实现风格。

- StaticIL：两处目标早退各只替换一次；栈平衡保持；替换目标是现有资格函数。先例是物品预生成与僵尸状态发送的单点 transpiler 契约。
- PureMemory：专用服为真、听主机为真、普通单机/客机为假。听主机不得在无信标、非 Horde 时仍走「直接 return」的单机分支。
- BuildArtifact：参与 Runtime 的 DLL SHA-256 一致。
- Runtime（与 Join Routing 共享一次 1 Host + 2 Guest，机制断言仍分列）：在普通 PEI 记录某已知区域僵尸初始数量，打死满足重生条件的僵尸，等待原版重生窗口，证明该区域之后出现新僵尸，并用诊断确认走进对齐分支。记录物品三类调用次数与区域，证明地面物品能被周期移除也能再生成，且无持续累加或数量失控。测试时间窗内若未自然触发重生，不得直接判失败，必须用诊断计数和可重复条件区分「窗口未到」与「早退仍在」。Horde/Beacon 不专项开场景，但本轮不得改变它们的原有语义。预生成与周期处理若造成重复刷物品，本票 Runtime FAIL，另开收缩票，禁止在本票内临时重构预生成。

## 范围外

- 僵尸或物品域的 SPI / Region Lease 迁移。
- 评审所述主机全量 tick 切片（性能）。
- 房主脚下树被误 disable、Collision 覆盖集。
- Join Routing、Route B fail-open、白名单中途关闭。
- 在本票内调整预生成策略。
- GitHub Release、版本号 bump（除非实现时构建元数据另有要求）。

## 补充说明

实施顺序：本规格先于 Join Routing 落地；两者无代码阻塞边。1 Host + 2 Guest 等两张都绿再跑一次。旧仓 GitHub #1/#2 是已修的握手 `hasProof` 超时，不是本规格的验收条件。
